# The continuing adventures

The active reading order for Jordan Hubbard’s AI-assisted project narratives.

## Scope and chronology

Audited on **2026-09-15**, using a six-month window beginning **2026-03-15 UTC**.
A participating repository is unarchived and has a coding-agent co-author credit,
with recorded AI-assisted activity inside that window. Inherited upstream AI
activity alone does not qualify a fork. Dependency-update bots do not count as
AI coding agents. Eligibility is a snapshot, not an instruction to delete stories
when a project becomes inactive.

Chapters are ordered by the earliest recorded AI-assisted commit in the reviewed
project history (Git committer timestamp, normalized to UTC). The full available
default-branch history was examined for ordering; fork-specific history excludes
upstream ancestry. Additional branches of excluded candidates were checked for
qualifying activity. Repository creation time is a fallback only; no fallback
was needed for this edition. Repository name breaks an exact timestamp tie.

Existing stories retain their original voice and fictional chronology. Their
historical technical claims are not a current feature audit. Part numbers and
navigation follow the commit evidence below, so the fictional sequence inside
an older story can differ from the reading order. Loom’s existing origin story
participates without being replaced by a second story.

- `ai-template` itself had no qualifying activity inside the window at audit time. This maintenance operation does not retroactively qualify a project.

## Maintenance

Use [the narrative skill](skills/narrative/SKILL.md) when explicitly asked to add
or repair a chapter. Preserve existing README content and stories. Recheck scope
and ordering evidence before renumbering; update both neighbors and this index
together. Do not infer missing AI participation from an absent story or trailer.

The machine-readable evidence is [chronicle.json](chronicle.json). Its base
commits and README hashes record exactly which content was preserved during
this retrofit.

### Validate the chain

```sh
# Read current default-branch READMEs using an authenticated gh CLI:
python3 scripts/check_chronicle.py --github

# Or inspect local clones; optionally verify the original retrofit snapshots:
python3 scripts/check_chronicle.py --repos-dir /path/to/clones --verify-retrofit
```

The checker validates ordering, unique chapters, headings, and reciprocal
neighbor links. Snapshot verification also checks original and edited README
hashes and preservation outside narrative sections. It does not re-audit current
eligibility or claim to validate every historical statement in a story.
