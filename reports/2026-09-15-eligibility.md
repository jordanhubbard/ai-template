## Preservation and validation

- Original and edited README SHA-256 hashes and base commits are recorded in [chronicle.json](../chronicle.json).
- Removing a newly inserted narrative restores the original README, apart from a required blank separator for the one-line dotfiles README.
- For existing narratives, README content outside the story section is byte-for-byte identical. Within those sections, changes are confined to navigation, obsolete chronological references/counts, and the provenance claim that an absent story meant no AI involvement.
- Existing headings are retained, including Loom’s `The Story of Loom`, so established anchors keep working.
- The read-only checker verifies chronological order, unique parts, all 19 headings, and reciprocal previous/next links. A deliberately broken neighbor was rejected.
- GitHub’s Markdown API rendered every chapter heading and navigation block successfully.
- No destination license, assistant configuration, application source, or build/test configuration was included in the retrofit.

## Historical ordering limits

Git history records the earliest available credited AI contribution, not necessarily
the day the project was conceived or the first uncredited use of an assistant.
The index deliberately distinguishes that evidence from fictional chronology in
preserved stories. Retired project names do not occupy active chapter slots.
